How the scores work

Every {{ w }} is treated as one document made of the skills extracted from it. A skill's synonyms have already been merged by the clustering step, so "python" and "python scripting" count as one skill.

Within one {{ w }}

TF
times the skill appears in the {{ w }} / all skill mentions in that {{ w }}. It is the skill's share of the {{ w }}.
Lift
TF / average TF. Above 1 means this {{ w }} gives the skill more room than the average {{ w }} does.

Across all {{ ws }}

Average TF
the mean of the skill's TF over all {{ ws }}, counting 0 where it is absent. Large and small {{ ws }} count equally.
Smoothed IDF
ln((1 + M) / (1 + df)) + 1, where M is the number of {{ ws }}{% if ds %} ({{ ds.n_groups }} here){% endif %} and df is how many contain the skill. It is never 0.
Score
average TF x smoothed IDF. One number per skill, so skills can be ranked and compared across all {{ ws }}.
TF-IDF
TF x ln(M / df). Useful for finding what makes one {{ w }} different from the others. A skill found in every {{ w }} scores 0, which does not mean it is absent.

Modules against the job market

Job demand
times the skill is mentioned in the job text / all skill mentions in the job text. Job text chunks containing the skill are also counted, to show how widespread it is.
Taught
a skill counts as taught when at least one {{ w }} has it. Breadth is the fraction of {{ ws }} that have it, not how deeply it is covered.
Job demand covered
adds up the job demand of all skills a {{ w }} has (or, overall, all skills that any {{ w }} has). It is the share of what the job text asks for that the {{ w }} touches.
Mentions in jobs
the share of a {{ w }}'s own skill mentions that are on skills the job text also asks for.
Gap score
job demand x (1 - fraction of {{ ws }} that have the skill). It is highest for skills employers ask for often that few {{ ws }} carry, and 0 for skills not in the job text.

Which one answers which question

QuestionUse
Which skills matter most across everything?Score, or average TF
Where is one skill emphasised most?TF or lift for that skill (the skill page)
What is this {{ w }} known for?TF-IDF or lift (the {{ w }} page)
Which skills do employers ask for that we do not teach?Gap score and the "In jobs, not taught" list (Job market fit)
Is a skill present at all?The "In" column and the mention counts

Read with care

  • A mention is not evidence of how deeply something is taught. The extraction recorded no proficiency level.
  • Small {{ ws }} give noisy shares: a skill mentioned once in a {{ w }} with 50 mentions looks as large as a skill mentioned 10 times in a {{ w }} with 500.
  • The job comparison depends on the job text. If it holds few postings or roles unrelated to the programme, the figures describe that text, not the job market.
  • Job rows and module rows are clustered together, so a wrong merge of two different skills can create a false match between a module and a job.
  • Only module material is scored here. Job postings take part in the clustering but have no {{ w }}, so they are not in these tables.
  • Skills are extracted by a language model and merged by an embedding threshold, so both steps can add errors.
